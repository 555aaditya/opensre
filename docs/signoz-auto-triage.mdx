title: "SigNoz bounded triage demo"
description: "Connect SigNoz or provision a disposable payment-alert demonstration"
---

Use `/triage` in the interactive shell or `uv run opensre triage` in a terminal.
Every investigation is foreground, read-only, and discarded after its report is
printed.

## Run the self-contained demo

```sh
uv run opensre triage demo
```

OpenSRE downloads checksum-verified, pinned releases of SigNoz Foundry and the
OpenTelemetry Demo, then starts an isolated Docker Compose environment. It
creates a viewer-only query key, configures a temporary authenticated webhook
and payment-error alert, enables `paymentFailure`, waits for a real native
SigNoz firing notification, and runs one bounded investigation.

You need:

- Docker Desktop or Docker Engine with Compose v2;
- Linux, macOS, or Linux in WSL on amd64/arm64;
- at least 5 GiB assigned to Docker and 15 GiB free disk;
- Internet access for release and container-image downloads; and
- a configured OpenSRE model. Provider charges may apply.

OpenSRE does not install or start Docker itself. SigNoz and application UI ports
bind only to loopback. The command disables the injected fault and removes the
temporary alert and webhook before it exits, but leaves the stack available for
inspection. It prints the SigNoz URL, admin email, path to the mode-`0600` admin
password file, and cleanup command.

```sh
uv run opensre triage demo cleanup <demo-id>
```

Cleanup validates the demo namespace before removing its containers, networks,
and volumes. It never prunes Docker or removes unrelated resources. If setup is
interrupted, start a fresh demo and use the printed cleanup command for the old
ID; setup is intentionally not resumable.

## Connect an existing SigNoz

```sh
uv run opensre triage connect
```

This reuses OpenSRE's normal SigNoz integration setup. Supply the SigNoz URL and
a read-only service-account API key. It does not install SigNoz or configure a
persistent webhook.

Run a one-off investigation with an exact service name:

```sh
uv run opensre triage run --service payment --window-minutes 30 \
  --symptom "checkout failures increased"
```

The window must be between 1 and 60 minutes. The investigator can query only the
selected service through scoped logs, metrics, and traces tools. It cannot
change the SigNoz URL, credential, or time bounds; it has no shell, remediation,
persistent tasks, or memory. A run is limited to 12 tool calls, 8 model calls,
10 rows per query, and 180 seconds.
